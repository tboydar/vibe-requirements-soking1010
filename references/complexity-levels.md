# 數位空間複雜度的五個層級

每個數位產品都可以對應到一個複雜度層級。層級越高，需要處理的「人與人之間的關係」就越複雜。判斷正確的層級，能避免過度設計（殺雞用牛刀）或設計不足（後面才發現要大改）。

## Lv1：個人工作室（工具）

**隱喻**：你在自家書房組裝的一張電腦桌。

**核心邏輯**：只有你擁有這個系統的使用權，工具的擺放、流程完全隨你高興。

**技術特徵**：
- 不需要登入系統
- 資料儲存在本機端（手機或電腦）
- 不需要考慮多人同時操作

**典型案例**：個人記帳工具、個人筆記 App、本地端計算器

**開發重點**：快速實現功能，介面簡潔好用即可。

## Lv2：私人辦公室（內部系統）

**隱喻**：一間私人公司辦公室。同一家公司的人才能進來。

**核心邏輯**：雖然大家都在同個空間，但有「職位分工」——老闆可以看到財報資料夾，員工只能看到自己的打卡記錄。

**技術特徵**：
- 需要身分驗證（登入）
- 需要權限分級（不同角色看到不同內容）
- 資料存在伺服器端，多人共用

**典型案例**：HR 人事系統、公司內部專案管理工具、團隊知識庫

**開發重點**：設計「誰可以看什麼、做什麼」的權限邏輯。

## Lv3：服務門市（前台與後台）

**隱喻**：一家連鎖便利商店。空間切分為二。

**核心邏輯**：
- **後台**：店員（內部人員）拿著鑰匙進去操作 POS 機、點貨。
- **前台**：不特定的路人（外部用戶）可以進來拿商品、結帳。

**技術特徵**：
- 兩套不同的使用介面（前台重體驗，後台重效率）
- 同一份資料，不同的操作邏輯
- 外部用戶可能需要註冊

**典型案例**：餐廳掃碼點餐系統（消費者 + 店員接單）、電商網站（消費者 + 賣家後台）、預約系統

**開發重點**：處理「內外有別」的體驗——後台重效率和防呆，前台重動線引導和美觀。

## Lv4：大眾運動場（單一品牌的開放式平台）

**隱喻**：一座全天候開放的運動中心。只有一個經營者（平台方），所有進場的人都直接對平台負責。

**核心邏輯**：感受不到「內部店員」在裡面服務，所有人（不特定用戶）都可以進去註冊使用、互相交流。

**技術特徵**：
- 大量用戶同時操作
- 用戶之間有互動（留言、按讚、分享）
- 需要處理「資源搶奪」（確保兩個人不會同時預約同個球場）
- 用戶資產管理（個人檔案、內容、積分）

**典型案例**：社群平台、論壇、線上學習平台、共享經濟平台

**開發重點**：用戶資產管理、高併發處理、內容審核機制。

## Lv5：數位百貨商場（多租戶 SaaS 系統）

**隱喻**：營運一間大型百貨公司。

**核心邏輯**：最複雜的層次——
- **後台的後台**：你是百貨公司老闆（SaaS 供應商），提供空間。
- **商家的後台**：不特定的櫃位老闆（租戶）進駐，管理他們自己的商品與店員。
- **商家的前台**：另一群不特定的消費者，進去各個櫃位買東西。

**技術特徵**：
- 三層角色：平台管理者、租戶（商家）、終端用戶
- 資料完全隔離：A 櫃位的老闆絕對看不到 B 櫃位的帳冊
- 每個租戶可以客製化自己的空間
- 需要計費和訂閱機制

**典型案例**：開店平台（如 Shopify）、企業 SaaS 工具、多租戶 CRM

**開發重點**：資料隔離、租戶管理、計費系統、可客製化的子系統。

## 如何判斷你的產品在哪一層？

依序問自己這些問題：

1. **只有我自己用嗎？** → 是 → Lv1
2. **使用者都是同一個組織內部的人嗎？** → 是 → Lv2
3. **有「服務提供方」和「服務接受方」的區別嗎？** → 是 → Lv3
4. **所有用戶都是平等的，可以互相互動嗎？** → 是 → Lv4
5. **會有「第三方入駐」、每個入駐方有自己的客戶嗎？** → 是 → Lv5

注意：實際產品可能跨越多個層級。例如，一個 Lv3 的餐廳系統，如果加上「多家餐廳入駐」的概念，就升級到 Lv5。先從最小可行的層級開始，之後再擴展。
