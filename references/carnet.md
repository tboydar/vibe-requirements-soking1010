# CARNET 需求訪談框架

CARNET 原意是「通行證」，象徵當我們掌握這六大要素，就能進入需求方的世界，理解背後的真實動機與限制。

## 六大面向

### C — Constraint（限制）

需求方在資源、時程、人力或組織結構上的限制條件。

引導問題：
- 專案的預算與時間範圍大概是多少？
- 有哪些規定或條件是不可動搖的？
- 哪些部門或環節可能會卡住流程？

### A — Aspiration（期待）

需求方對於成功樣貌的想像與描述。

引導問題：
- 您最希望這個專案完成後能帶來什麼？
- 如果要用一個具體成果衡量成功，會是什麼？
- 對您來說，這個專案的最佳狀態是什麼？

### R — Role（身份）

眼前人的身份、權限與決策影響力。

引導問題：
- 您在這個專案中扮演什麼角色？
- 誰會是最終的決策者？
- 其他哪些利害關係人會參與？

### N — Need（需求來源）

專案為什麼此時此刻出現？背後的觸發點。

引導問題：
- 這個需求是怎麼被提出的？
- 最近發生了什麼事件讓專案變得急迫？
- 如果這次專案沒有執行，會有什麼影響？

### E — Experience（經驗）

過去類似的嘗試與學到的教訓。

引導問題：
- 過去有沒有做過類似專案？結果如何？
- 哪些經驗會影響這次規劃？
- 之前最大的挑戰或阻礙是什麼？

### T — Trust / Thoughts（信念）

需求方對「應該怎麼做」的信念、偏好與預設立場。

引導問題：
- 您認為這類專案要怎麼做才會成功？
- 選擇合作夥伴時，您最看重什麼？
- 在您心中，什麼樣的失敗是不能接受的？

## 建議訪談順序

1. 先問 **Role**（誰是誰？誰決策？）
2. 探索 **Need** 與 **Aspiration**（為什麼做？想達到什麼？）
3. 追溯 **Experience**（過去的經驗教訓）
4. 挖掘 **Constraint**（資源與現實限制）
5. 深入 **Trust**（需求方的信念與偏好）

## 在 Vibe Coding 場景的簡化用法

對於獨立開發者或小團隊，CARNET 可以簡化為自問自答：

- **我是為誰做這個？**（R）
- **為什麼現在要做？**（N）
- **做完之後最理想的結果是什麼？**（A）
- **我之前試過什麼？學到什麼？**（E）
- **時間、預算、技術能力有什麼限制？**（C）
- **我相信什麼樣的做法是對的？**（T）
